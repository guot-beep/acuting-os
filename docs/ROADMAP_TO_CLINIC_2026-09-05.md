## 4. 病症/證型線的做法(拓關的派工內容)

**規則正本:`docs/CONDITION_CARD_TEMPLATE.md`。驗證器:`scripts/validate-condition-standard.js`。**

### 第 0 步(擋路的,必須先做):證型命名空間收斂

證型現在有**兩套不相容的 id**,直接開填會讓每一條連結變成擲骰子:

| 檔案 | 筆數 | id | 角色 |
|---|---|---|---|
| `pattern_registry.json` | 61 | `pattern.blood_stasis` | **ID 權威** |
| `pattern_library.json` | 50 | 同命名空間(48 筆重疊) | 內容層 |
| `tcm_pattern_canon.json` | 140(134 unique,**6 個重複**) | **`pat.氣血不和`** | **降級為匯入暫存** |

`registry ∩ canon = 0` —— 兩個獨立宇宙。做法見 DECISIONS **D10**:
建 `data/config/pattern_alias_map.json` 對照,不改也不刪既有 id。

**一天的事。之後再做是一個月。**

### 第 1 步:150 筆病症的基準線

`node scripts/validate-condition-standard.js --worklist --all` 的 2026-08-05 基準:

```
150 筆 · 0 筆乾淨 · 631 個缺陷
  C3  entity_type 缺失          150   ← 西醫病名/中醫病名沒分類
  C5  _zh 有內容但 _en 空       300   ← etiology 與 western_pathology 全部只有中文
  C4  完全沒有 red flags         95   ← 安全,最優先
  C7  來源欄位漂移               85   ← 四個欄位做同一件事
  C9  _en 有內容但 _zh 空          1
  N1  內嵌 blob 未提升成關係     66 筆(提示,不擋)
```

修復順序:**C4 安全 → C3 分類 → C7 來源合併 → C5 補英文**。

### 第 2 步:垂直切片先於量產

不要 150 條一起推進。**先把婦科 25 條做到 0 defect**,理由:
gyn 是唯一已填過的批次、ABORM 是最接近的認證、SOAP 已有 cycle 欄位、
而且 9/5 進診所後你最可能遇到的就是這類病人。

一條鏈走通(病症 → 證型 → 穴位 → 方劑 → red flags → 病例),
其餘 125 條就是複製流程。走不通,做 150 條也只是 150 個半成品。

### 第 3 步之後的順序(Ting 已定)

```
病症/證型  →  藥理(西藥卡)  →  頭皮穴 + 耳穴補強  →  借書登入資料
```

**藥理層開工前需要先有 `docs/MEDICATION_CARD_TEMPLATE.md` +
`validate-medication-standard.js`** —— 跟這次一樣,量尺先於量產。
西藥卡的安全欄位(交互作用、禁忌、劑量)比中藥更不能猜,那一層的模板我另外寫。
