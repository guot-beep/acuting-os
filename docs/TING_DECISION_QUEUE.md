### 為什麼 PR #59 會一再「壞掉」,以及已經做了什麼

**症狀**:PR 看起來沒有紅燈,但也沒有任何 CI run。

**成因有兩層**:

1. `validate.yml` 的觸發條件是 `pull_request` 加上 `push: branches: [main]` ——
   **長命分支自己的 push 不會跑 CI**,它唯一的覆蓋來自 PR 事件。
2. PR 一旦與 base 衝突,GitHub 就不建 merge ref,**PR 事件產生的 run 是零**。

兩者相乘 = 分支在衝突期間完全沒有 CI,而且**不是紅燈,是沒有燈**。
`codex/pattern-v2` 領先 main 五百多個 commit,main 每收一個動到同檔案的 commit
(例如 `213f8d18` 的手機 lazy-render 改了 `js/knowledge.js`)就會衝突一次。

**已做的兩個修正**:

- `push: branches: [main, 'codex/**']` —— 分支自己的 push 一定跑 CI,
  **push 事件不受 PR 可合性影響**,單點失效解除。
- `scripts/check-branch-mergeable.js` 加入 CI(只在 push 事件跑):
  落後或衝突就**紅燈**,並印出怎麼修。它把「安靜消失」變成「明確失敗」。

**根本解**還是縮短分支壽命:571 個 commit 的分支與持續前進的 main 必然反覆衝突。
分批落地會讓這個問題自己消失 —— 但那要等 landing PAUSE 解除。

### E6 實作西藥詳卡,讓 25 個黑框警告第一次上畫面(A0c 的第一步)

「查看西藥卡」按鈕先前是壞的:`openKnowledgeDetail` 只認得 formula 與 herb,
pharm 查不到記錄就靜靜 return。按鈕在、按了什麼都不會發生。

**這是 E1–E5 以外的方向,所以我特別說明為什麼我自己做了**:E1–E5 都是「不顯示不可信的
內容」,這一項是「顯示原本看不到的內容」。判準是**來源**:西藥這些欄位全部來自官方
藥品標籤(DailyMed / MedlinePlus),而且 `validate-pharm-standard.js` §0 已經在守
——安全欄位沒有 verified_exact 的官方來源就不准存在。與方劑那 26 段抓取來的效益宣稱
(A0b)剛好相反,**那批仍然全部隱藏**。對一張華法林的卡,不顯示黑框警告才是危險的一邊。

顯示順序照臨床急迫性:黑框警告 → 禁忌 → 警語 → 嚴重不良反應 → 孕哺 → 交互作用。
另外兩頁是藥理與中西醫關聯,後者明確標示「本庫註記,非官方標籤」。

**過程中修掉一個會誤導的地方**:詳卡外殼原本沿用中藥版,於是華法林卡上出現
「性味 待補」「歸經 待補」。那不是缺資料 —— **那些概念不適用於西藥**,印「待補」
等於暗示遲早會補上,是渲染層在說資料沒說過的話(與假劑量 `6~15g` 同一種錯)。
改成分類 / 作用標的 / 官方標籤三格,而且用列表卡已經在用的同一組解析,不另外猜欄位名。

**實測**:59 張卡全開,**25 個有黑框警告的全部顯示成功**,0 個中藥欄位外洩,0 個丟錯;
方劑與中藥卡不受影響。

並刪掉 `pharmPanels()`。資料一個字沒動。
