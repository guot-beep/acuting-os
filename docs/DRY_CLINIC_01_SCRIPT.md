# Dry Clinic 01 — 操作單(虛構病人 A,五診)

**這份不是測試,是排練。** 目的不是看 validator 綠不綠 —— 那些我已經跑過了。
目的是讓你**真的坐下來當一次使用者**,把「哪一步讓我覺得煩」記下來。

規則只有兩條:

1. **不要停下來修東西,也不要跟我說「這裡怪怪的」就開始改。** 照走完,把煩的地方寫進最後那張表。
2. **只留 Top 5。** 全部寫下來會變成新的待辦黑洞;只挑最煩的五個,我直接修那五個。

---

## 開始之前

**用獨立的 port 跑,不要用你平常那個。** 這樣虛構病人不會混進你真實的 33 筆病例裡,
也不用事後刪(這個專案不做硬刪,刪不乾淨)。

```bash
export PATH="/c/Program Files/nodejs:$PATH"; node scripts/dev-server.js 8399
```

然後開 `http://127.0.0.1:8399/index.html`,按「病例」工作區。
跑完直接關掉視窗就好,那個 origin 的資料跟你平常用的完全分開。

計時:**每一診從按「新增 SOAP」到存檔完成,自己看一下時鐘。** 目標是一般回診 ≤ 5 分鐘。
第一診會比較久(要建病例),不算。

## 病人 A 的故事

> 42 歲女性,右肩痛三個月,夜裡痛醒。已經吃了兩個月的 NSAID,效果遞減。
> 因為心房顫動長期服用 warfarin —— 這一條很重要,第 4 診要用到。
> 工作是牙醫助理,長時間手臂上舉。

五診的骨架:

| 診次 | 這一診要發生什麼 | 你在測的是 |
|---|---|---|
| 1 | 建病例 + 初診,基準值 pain 7 / sleep 4 | 建檔要打多少字 |
| 2 | 一般回診,pain 6,沒什麼變化 | **最常做的那一種診次,順不順** |
| 3 | 拔罐後瘀青 → 記不良事件 | 出事的時候找不找得到地方記 |
| 4 | 病人自己加了魚油 → 記用藥變動 | **黑框警告有沒有跳出來**(warfarin + 魚油) |
| 5 | 換方 + 收尾,pain 3 / sleep 6 | 看得出病程走向嗎 |

### B. 把 warfarin 記成結構化用藥

病例存好後,在病例詳情裡找「用藥與補充劑 Meds & Supplements」,按 **+ 新增 Add**。

| 欄位 | 填什麼 |
|---|---|
| 類型 Type | 藥 Drug |
| Agent ID(選填) | 下拉選 **華法林 / drug.warfarin**(**一定要選**,這一診的重點就在這) |
| 名稱 Name | 選了 Agent ID 就可以留空 |
| 劑量 Dose | `5 mg` |
| 頻率 Frequency | `QD` |
| 開始(約)Start | 留空或填一年前 |
| 已在使用 Already in use | **勾起來**(來看診之前就在吃了,不是這次開的) |
| 來源 Info source | 病人自述 |

存好之後 **停下來看一眼那一列**。

> ✅ **應該要看到紅框的「⚠️ 黑框警告 BOXED WARNING」,寫著大出血與監測 INR。**
> 如果沒看到,那是 bug,在最後那張表寫「warfarin 沒跳黑框」。
>
> 下面還會有一條收起來的「禁忌 Contraindications(20)」。點開看一眼就好 ——
> 我想知道 **20 條攤開來對你是有用還是煩**。

### C. 第 1 診 SOAP(按「新增 SOAP」)

| O - Objective | `右肩外展受限,肩峰下壓痛。舌淡暗苔薄白,脈弦。` |

| 主證型 Primary TCM pattern | **用欄位旁的挑選器選 肝氣鬱結**,不要自己打字(打字會存不成結構化 id) |
| P - Plan | `疏經活絡,行氣化瘀` |
| 用穴 Acupuncture points | `LI15 · LI4 · SI9 · ST38`(這是自由文字欄) |

**Outcome 數值**(在「Outcome metric links」下面,有一整排結構化欄位,共 12 個):

- 疼痛(0 無痛 / 10 最痛)→ `7`
- 睡眠品質(0 最差 / 10 最好)→ `4`

其他十個(睡眠時數、壓力、情緒、精神體力、腹脹、入睡時間、夜醒次數、排便頻率、
效果維持時間、PGIC)這次**一律留空**。

> 這裡也在測一件事:**一次看到 12 個欄位、只填兩個,感覺如何?**
> 如果你覺得應該只顯示跟這個病例相關的幾個,那就是一條摩擦點。

存檔。

> ⏱ **第 1 診總共花多久?**

**用藥變動**:回病例詳情的用藥區,按 **+ 新增 Add**。這次**加兩筆**,故意做對照:

第一筆 —— 有連結卡片:

| 欄位 | 填什麼 |
|---|---|
| 類型 Type | 補充劑 Supplement |
| Agent ID | 下拉選 **Omega-3 脂肪酸 / supp.omega_3** |
| 劑量 Dose | `1000 mg` |
| 已在使用 | 勾起來(上個月開始的) |
| 來源 Info source | 病人自述 |

第二筆 —— **故意不連卡片**:

| 欄位 | 填什麼 |
|---|---|
| 類型 Type | 補充劑 Supplement |
| Agent ID | **留空** |
| 名稱 Name | `某廠牌關節保養膠囊(病人自述,成分不明)` |
| 已在使用 | 勾起來 |

存好之後 **停下來看那三列**,這是這一診真正在測的東西:

> ✅ **warfarin** —— 紅框黑框警告(大出血、監測 INR)
>
> ✅ **Omega-3** —— 黃框「⚠ 交互作用註記」,內容大意是高劑量 omega-3 會延長
> 出血時間、使用抗凝血劑者需評估,旁邊帶一個 `anticoagulant` 標記,
> 下面附來源 NIH ODS
>
> ✅ **關節保養膠囊** —— 灰字「⃠ 未做安全檢查:沒有連結知識庫卡片」
>
> 三種顏色代表三件不同的事:**有警告 / 有註記 / 沒查過**。
> 最後那一句是故意的:它不是說這個膠囊安全,是說**系統根本沒查**。
>
> **系統不會替你做 warfarin + 魚油的交互作用判斷** —— 它不知道這個病人同時在吃
> 什麼,那個判斷是你的。它只負責兩件事:把有出處的註記端到你面前,以及
> 不要在沒查過的時候假裝查過了。
>
> **我想知道你的真實反應:**
> 1. 黃框那條註記,對你當下的判斷有幫助嗎?
> 2. 灰字那句「未做安全檢查」是有用還是噪音?如果是噪音,說出來,我改成
>    只在有連結的品項旁邊提。
> 3. 你會不會期待系統直接說「這兩個一起吃要小心」?如果會,我們得談那是不是
>    該做 —— 那是另一個層級的東西(交互作用引擎),做錯了比不做更危險。

## 走完之後,做這六件事

依序做,每一步都可能出問題:

1. **關掉分頁,重開 `http://127.0.0.1:8399/index.html`**
   → 病人 A 的五診都還在嗎?用藥、不良事件、outcome 數值有沒有掉?

2. **回頭編輯第 2 診**,把 S 加一句話,存檔,再 reload
   → 改的那句在嗎?其他四診有沒有被動到?

3. **看第 5 診的 Visit Brief**(病例詳情上方)
   → 上次治療那一塊,方劑應該顯示「桂枝湯」而不是 `formula.gui_zhi_tang`
   → **八列裡哪幾列你真的會看?哪幾列是雜訊?**

4. **看病程泳道 Timeline**
   → 昨晚補了三條 lane:證型、用穴、方劑。方劑換方那一診會有一條垂直虛線
   → 滑鼠移到標記上會顯示那一診的內容(用穴清單、方劑名)
   → **軸兩端的日期對嗎?** 應該是你第 1 診與第 5 診的實際日期
     (這裡本來有個 bug,每一診都早一天,昨晚修了 —— 幫我確認真的好了)
   → 五診的走向看得出來嗎?還是只是一堆點?

5. **按工具列的「診務回顧 Practice Audit」**
   → 回診率、療效判定分佈、Outcome 變化、知識缺口有沒有出現?
   → 疼痛那列應該寫「可對照:Farrar JT 2001」,睡眠品質那列應該寫「無公認閾值」
   → **知識缺口那一區列出來的卡片,是你真的想補的嗎?**

6. **匯出 → 匯入**
   工具列「匯出病例」存成檔案 → 關掉分頁重開 → 「匯入病例」把它讀回來
   → 五診、用藥、不良事件、outcome 數值、AVS 摘要全部都在嗎?
   → 有沒有出現重複的病例?
