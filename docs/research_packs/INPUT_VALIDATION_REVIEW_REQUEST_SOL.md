## 背景

AcuTing OS 是 Ting 個人的中醫學習與臨床工作站(私人、不公開)。裡面有一段
「診前資料」流程:病人在自己手機上填一份表單,產生一段 JSON,醫師在診間把它
貼進病歷系統預填欄位。

這段程式碼**還沒有被用在真實病人身上** —— 我們刻意把它擋著,直到驗證邏輯
被審過。過去幾輪內部檢查一直發現同一類問題:**驗證規則寫得不夠準確**,
有時該擋的沒擋(壞資料變成臨床數值),有時不該擋的擋了(合法輸入被拒絕)。

我們需要第二雙眼睛看這些規則本身寫得對不對。

## 想請你回答的問題

### 第一組:規則寫得準不準(最重要)

我們最近把幾條規則改嚴了,擔心**誤傷合法輸入** —— 這種錯比漏放更難發現,
因為病人填了正常的值、系統說不行,而沒有人會去查為什麼。

1. **數值格式**:我們要求數字必須是「純十進位」寫法(不接受 `1e-7` 這種指數形式),
   理由是存檔端只認純十進位。**這條規則會不會擋掉某個合理的填答?**
   欄位是:疼痛 0–10 整數、睡眠時數(可小數,無上限)、壓力/心情/精力 0–10 整數、
   整體改變感受 1–7 整數。

2. **時間格式**:`filledAt` 要求 ISO 8601 且必須是真實存在的日期(`2026-02-31` 拒收)。
   **有沒有合理的時區/格式寫法會被誤拒?**

3. **看不見的字元**:我們會把病歷文字裡的控制字元與格式字元清掉,但**保留**
   ZWJ(U+200D)與 ZWNJ(U+200C),因為它們在 emoji 與波斯文/印地文的正字法裡有意義。
   **這個界線畫得對嗎?** 還有哪些看不見的字元其實是文字的一部分、不該清掉?
   反過來,還有哪些應該清掉但我們留著?

4. **識別碼欄位**(病歷代碼、表單流水號):這兩個欄位我們把**所有**看不見的字元
   都清掉,因為系統用它們做逐字比對。**這樣處理有沒有副作用?**

### 第二組:錯誤訊息會不會洩漏內容

這是上一輪找到的實際問題:JSON 解析失敗時,瀏覽器產生的錯誤訊息會**內嵌一段
原始輸入**,而那段訊息被顯示在對話框裡。如果醫師貼錯剪貼簿,病人寫的東西就
出現在畫面上。我們已經把所有解析失敗的訊息改成只報「長度」不報內容。

想請你檢查:**還有沒有別的地方會把原始資料帶到使用者看得到的位置?**
(例如匯出/匯入失敗的提示、瀏覽器 console、頁面上的錯誤區塊、剪貼簿…)

另外:**只報字元長度算不算洩漏?** 我判斷不算,想聽反面意見。

### 第三組:醫療內容(你的本行,與程式碼無關)

`docs/research_packs/FORMULA_INTERFERON_PROVENANCE_TRACE.md` 記錄了一個發現:
有幾張方劑卡把「與干擾素併用」寫成**效益**,但有來源的證據其實是**風險**
(間質性肺炎),而且只適用於小柴胡湯那一張。

其中最要緊的是:唯一設定為**對外可見**的那張卡(十全大補湯),恰好是先前
沒被點名的那張。

→ 想請你做一份清單:**還有哪些對外可見的卡片,帶著沒有來源的「效益」敘述?**
這可以純粹讀 `data/herbs/formulas.json` 產出,不需要跑任何程式。

## 回覆方式

你不能寫進 repo,所以**把整份審查結果當回覆內容輸出**(完整 markdown、可直接落檔),
Ting 會轉交,由我存成 `docs/research_packs/INPUT_VALIDATION_REVIEW_2026-08_SOL.md`。

每一條請寫成:

```
### R-n  <一句話>
在哪裡: <檔案/函式/欄位>
疑慮:   <你的推理,不需要證明>
怎麼確認: <一個具體的輸入或步驟,讓下一個人可以直接驗>
如果成立有多嚴重: 高 / 中 / 低
怎麼判斷是虛驚: <反證條件>
```

最後附一節「**我沒有涵蓋的部分**」,誠實列出你這輪沒把握或無法從讀碼判斷的區域。

你的判斷不需要百分之百正確 —— **價值在於指出實作者自己想不到的方向**。
證明或推翻是下一棒的事。
