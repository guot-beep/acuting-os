## 二、要修的：§0 違規（2 首）

### 發生了什麼

| 方劑 | 欄位 | 變化 |
|---|---|---|
| 桂枝湯 | `actions_zh` | 16 → 3 |
| 桂枝湯 | `pattern_indications_zh` | 14 → 5 |
| 桂枝湯 | `contraindications_zh` | 4 → 3 |
| 小青龍湯 | `actions_zh` | 31 → 3 |
| 小青龍湯 | `pattern_indications_zh` | 31 → 5 |

### 診斷是對的

桂枝湯原本的 `actions_zh` 16 條**根本不是功效**，是煎服法、藥後護理和現代應用被塞進了功效欄位：

> 「服藥後喝粥：服藥後片刻，喝熱粥，益胃氣以助藥力…」
> 「呼吸系統：常用於普通感冒、流行性感冒…桂枝湯對體溫有雙向調節作用…」
> 「婦科：月經病（寒滯痛經、經行後期…）」

你換成「解肌發表／調和營衛／散風寒、止痛」——**這才是桂枝湯真正的功用，換得對**。這正是 `FORMULA_CARD_TEMPLATE.md` 教訓 1 講的「問題從來不是沒東西，是東西放錯地方」。

### 但處理方式錯了

**那些內容被刪掉了，不是搬走。**

我確認過：「呼吸系統」開頭那整段在 main 存在，在你的分支**完全不存在**——沒有進 `applications_zh`、沒有進 `modern_research_zh`、沒有進 `preparation_zh` 或 `administration_zh`，任何欄位都查不到。

§0「只加深，不刪除」的意思是**搬家，不是刪除**。發現內容放錯欄位時：

- ✅ 正確：把它移到對的欄位，原欄位換上正確內容
- ❌ 錯誤：把原欄位換上正確內容，舊內容直接消失

這一條之所以嚴格，是因為那些現代應用段落是有來源、有價值的臨床資料，重新蒐集要花很多時間，而刪除在驗證器上完全看不出來——`validate-formula-standard` 全部 PASS。**驗證器 PASS 不等於沒有損失。**

### 請這樣修

把被刪的內容搬到對的欄位，**不要還原回 `actions_zh`**（那本來就放錯）：

| 原本被刪的內容 | 應該去的欄位 |
|---|---|
| 「呼吸系統：…」「消化系統：…」「循環系統：…」「運動系統：…」「神經系統：…」「內分泌系統：…」「婦科：…」「兒科：…」 | `applications_zh`（現代應用） |
| 「服藥後喝粥…」「溫覆微汗…」「獲效停服…」「未效守方…」 | `administration_zh`（服法與藥後護理） |
| 「藥後禁口：服藥期間禁忌生冷、粘滑…」 | `administration_zh`，或 `cautions_zh` |

原始內容可以從 main 取回：

```bash
git show main:data/herbs/formulas.json
```

小青龍湯同樣處理。

### 另外：禁忌不要精簡

桂枝湯 `contraindications_zh` 從 4 條變 3 條，其中這類細節沒了：

> 「不正確用此方，會產生高熱，自汗，口干，心悸，煩躁等證。」

**誤用後果的描述是安全資訊，不是冗詞。** 禁忌欄位寧可長，不要精簡。如果覺得原文太雜，可以整理句子，但不能減少實質資訊。

## 四、下次做同類任務時

驗證器抓不到「內容被搬走或刪掉」。改欄位之前，先問自己一句：

> **我要換掉的這些內容，是垃圾，還是只是放錯地方？**

如果是放錯地方——**先找到它該去的欄位，搬過去，再換**。順序不能反，一反就會忘記搬。
