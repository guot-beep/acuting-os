## 一、這個任務是什麼

方歌是背誦用的韻文，例如麻黃湯：

```
麻黃湯中用桂枝，杏仁甘草四般施。
發熱惡寒頭項痛，喘而無汗宜服之。
```

Ting 要用來記方劑組成。**卡片上「有才顯示、沒有整區不出現」**，所以缺的方不會有破口，不急著湊數量。

欄位與渲染都已經做好了，你只要填資料。

## 二、欄位規格（完整規格見 `docs/FORMULA_CARD_TEMPLATE.md` §1.1）

| 欄位 | 型別 | 必要性 |
|---|---|---|
| `formula_song_zh` | string | 抓到才建 |
| `formula_song_source_zh` | string | 知道出處才建，例如「出自汪昂《湯頭歌訣》」 |
| `formula_song_alt_zh` | string[] | 同一方有第二首方歌時才建 |
| `field_sources.formula_song_zh` | string[] | 實際來源（書名或網址） |

寫入範例（`formula.ma_huang_tang` 現況，照這個格式）：

```json
{
  "formula_song_zh": "麻黃湯中用桂枝，杏仁甘草四般施。\n發熱惡寒頭項痛，喘而無汗宜服之。",
  "formula_song_source_zh": "出自汪昂《湯頭歌訣》",
  "field_sources": { "formula_song_zh": ["湯頭歌訣（汪昂）"] }
}
```

## 三、硬規則（違反的話會被打回）

### 1. 沒抓到就**不要建欄位**

不要寫 `""`、不要寫 `"待補"`、不要寫 `null`。

理由：渲染層判斷的是「有沒有內容」，填空字串在卡片上跟沒填一模一樣，但覆蓋率統計會把它算成已完成。**這會讓 Ting 以為做完了，其實沒有。** 這是這個專案踩過最多次的坑。

### 2. 方歌要**逐字照抄**，一個字都不能改

這跟功效、主治那些欄位不一樣。功效可以整理歸納，方歌**改一個字就不押韻，背起來就是錯的**。不要精簡、不要改標點、不要把繁簡體混用後「順手統一」。原文長什麼樣就抄什麼樣。

### 3. 標明是哪一本書

同一首方在不同書的方歌**不一樣**。汪昂《湯頭歌訣》、陳修園《長沙方歌括》、《醫方集解》各有版本。抓到哪本就寫哪本。

不知道出處時：`formula_song_zh` 照填，`formula_song_source_zh` 就**不要建**，然後在 `field_sources.formula_song_zh` 放你抓到的網址。不要猜書名。

### 4. 一方多首方歌：主的放 `formula_song_zh`，其餘放 `formula_song_alt_zh`

**不要把兩首黏成一段。** 驗證器會抓超過 200 字的欄位。

### 5. 斷句用 `\n`

渲染時會轉成 `<br>`。不要用 `<br>`、不要用 `\\n`、不要塞 HTML。

### 6. 不要有拉丁字母

方歌是中文韻文。出現 3 個以上連續拉丁字母，代表混進了拼音或英文翻譯，驗證器會報 S3。

## 五、驗收方式

```bash
node scripts/validate-formula-song.js
```

會印出覆蓋率與格式問題。目前是**報告模式不擋**，但下列問題會被列出來，請在交付前清乾淨：

| 代碼 | 意思 |
|---|---|
| S1 | 欄位不是字串 |
| S2 | 空字串或佔位字（違反硬規則 1） |
| S3 | 含拉丁字母，混進拼音或英文 |
| S4 | 超過 200 字，可能黏了兩首 |
| S5 | `formula_song_alt_zh` 不是陣列 |

交付前也要跑：

```bash
node scripts/validate-formula-standard.js
```

確認沒有把別的欄位弄壞。
