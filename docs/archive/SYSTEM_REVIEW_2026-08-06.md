## 2. 高階規則補充(這次盤點發現還缺的)

### D12(PROPOSED)— 臨床層穩定契約:9/1 起 additive-only

寫進 `DECISIONS.md` 待 Ting 批准:

> **9/1 起,`data/clinical_cases/schema.sql`、病例的 localStorage 格式、
> 匯出檔格式一律只加不改不刪**(additive-only)。任何 breaking 變更要附
> 遷移腳本 + 在測試資料上演練過才能進。
> **理由**:9/5 之後那個 localStorage 裡是真的(去識別化)病例。一個欄位
> 改名就是資料遺失,而病例資料是 DECISIONS 說的「事後補不回來」的資產。
> UI 凍結管外觀,這條管資料 —— 兩個都要。

### R1 — 優先序仲裁規則(誰先做,吵架時用)

```
① 診所擋路(9/5 前的部署/dry run/病例層 bug)
② 安全欄位(紅旗/禁忌/刺深/交互)
③ 假數字修正(回報與實況不符,如 comparisons 41)
④ 考試高頻(Appendix/blueprint 覆蓋)
⑤ 內容加深
```

任何 agent 同時有兩件事可做時,照這個順序。寫進憲法 §C 末尾。

### R2 — 回報保鮮規則

> **`missing_report.json` 超過 7 天未更新 = 它自己就是一個缺陷。**
> 每條線收批時順手更新自己那層的數字(已在 handoff 格式裡),
> Claude 每週日跑一次全面 refresh。品質頁顯示 `last_quality_update`,
> 過期就標紅。

### R3 — 「宣稱要能被一行指令重現」

> Handoff 裡的每一個數字都要附上得到它的指令
> (`validate-X --json` / `--worklist`)。下一個 agent 用同一行指令重測,
> 對不上就以重測為準並記入 log。
> 這是 8/01 Codex「接手後實測、修正穴位數字」那次教訓的制度化。

## 3. 三方工作流(Claude Max · Codex · Antigravity Plus)

### 分工不變,節奏明確化

| | Claude Max(總指揮) | Codex(工程+精修) | Antigravity Plus(量產) |
|---|---|---|---|
| 強項 | 架構、跨檔、合併、判斷 | 精準轉換、validator、小 PR | 批量內容、初稿 |
| 專屬區 | `app.js`/`js`/`scripts`/`docs`/`clinical` | `data/acupoints`,`data/formulas+herbs` | `data/pathology` |
| **模型分層** | 高階:紅旗/鑑別/安全/合併 | 中高:四來源查證 | **低階跑 L5-A 機械批**(憲法 §E2) |

### 每日節奏(8/07 起)

```
早    各線 git pull → 開 branch → 從派工單/棘輪 worklist 取批
批中  10–15 筆一批,validator 過了才 commit,push 不過夜
晚    Claude 收攏:merge PR → 跑棘輪 --update 鎖進步 → 更新 missing_report
      → 用 $acuting-dispatch 產明天的批
Ting  每天 RV1 掃一點(中藥 0→37 證明可行);衝突或判斷題只到她這裡
```

### 併發規則(重申 + 一條新的)

- 一個檔案一個主人(憲法 §A);**只有 Claude merge 到 main**。
- 新:**同一條線同一時間只有一個 agent。** Codex 同時開奇穴+方劑要分開
  branch、分開 commit、分開 handoff —— 混在一起的批無法 revert。
