## 0. 先決定一件事:9/2 那天你用什麼開?(這題沒答,底下全部白做)

病歷存在瀏覽器裡,而且**綁定開啟網址**。這不是設定問題,是 localStorage 的
結構:`file://`、`http://localhost:<port>`、Cloudflare 部署網址是**三個互不
相通的資料庫**,系統在結構上看不到另外兩個。開錯書籤 = 病人看起來全部消失。

| 入口 | 手機可用 | 現況 | 風險 |
|---|---|---|---|
| `file://` 本機檔案 | ❌ | `PROJECT_LOG.md:118` 記載這是目前真機用法 | 同機多份 checkout 共用 localStorage;`legacy/index.html` 會直寫 v1 鍵造成污染(M2,未修) |
| `http://localhost:<port>` | ❌ | 需要本機起伺服器 | 換 port 或改用 `127.0.0.1` 就變成另一個資料庫(已有紅色警示橫幅) |
| Cloudflare 部署網址 | ✅ | **線上是 2026-08-09 的 build(`47026e5`)** | 見下方 §0.1 —— 這是目前最大的落差 |

## 1. 演練:照順序走,每一步都要看到指定的東西

用假病人,`patient_code` 用 `P-REHEARSAL-001` 這種一眼看得出是演練的字串。
**全程不要輸入任何真實病人資料。**

### Step 1 — 開 app,確認你在對的資料庫

- [ ] 病例工作區最上方那行「病歷資料庫入口:…」顯示的是你 §0 決定的那個網址
- [ ] 若顯示 `127.0.0.1` → 上方會有紅色橫幅,**停下來換網址**
- [ ] 若你之前記過病例卻顯示「這個入口目前有 0 筆病例」→ 開錯入口了,不要往下走

### Step 2 — 建第一個病例

- [ ] 「新增病例」→ 填 patient_code、主訴 → 存檔
- [ ] 病例列表出現這一筆

### Step 3 — 建第二個病例(不同 patient_code)⚠️ 這步在抓 M3

- [ ] 用**不同**的 patient_code 再建一筆
- [ ] 切到「病人總覽 Patient Workspace」→ **兩個 code 都要出現在病人列表**
- [ ] 若出現黃色橫幅「⚠ N 個病人代碼尚未建檔」→ 照橫幅上的原因處理。
      最常見是 `file://` 下 `crypto.subtle` 不可用 → 換成本機伺服器或部署網址再存一次

> 這一步過去會**靜默失敗**:病例存進去了、病人列表少一個人、只有 console 有痕跡。
> 現在會講話了(2026-08-24 M3 修復),但仍要親眼確認橫幅沒出現。

### Step 4 — 寫第一診 SOAP

- [ ] 「新增 SOAP」→ 填 S/O/A/P
- [ ] 用穴欄輸入中文或代碼(例如打「足三里」或「ST36」)→ 從下拉選,**不要手打 id**
- [ ] 選 7–8 個穴,填留針分鐘、手法
- [ ] **試一次分區導航**:對話框頂端那排晶片(上次/脈絡/S/O/A/P/生活/AE/成效),
      點「P 治法」應直接跳到治法區,不必捲
- [ ] 展開 P 區的「針刺參數 Needling parameters」,填進針數/深度/得氣/刺激/針具
      (選填;留空 = 未記錄,與「0 針」「未得氣」是不同的事實)
- [ ] 存檔 → 病例詳情出現這一診

### Step 5 — 寫第二診,測「沿用上次治療」⚠️ 這步在測速度

- [ ] 「新增 SOAP」→ 上次就診面板出現「沿用上次治療」按鈕
- [ ] 按下去 → 用穴/留針/手法/處置/方藥一次帶入,chip 顯示中文穴名
- [ ] **確認 S/O/A/P、療效、證型、治則、醫囑全部仍然是空的** —— 那些是今天要重新判斷的
- [ ] 下方會逐項告訴你帶了什麼、跳過什麼(已有內容的欄位不會被覆寫)
- [ ] 自己寫今天的 S/O → 存檔

### Step 6 — 產生診後摘要,檢查病人拿到的那張紙 ⚠️ 這步在防洩漏

- [ ] 在 SOAP 的「下次計畫」欄故意寫一句內部盤算,例如
      「若三次無明顯進展,考慮轉介影像學」
- [ ] 開診後摘要 checkout → 第 5 區「回診」**應該是空白的**
- [ ] 旁邊會顯示「SOAP 下次計畫(僅醫師端,不會自動進病人文件)」+「沿用這段」
- [ ] 按「沿用這段」→ 文字進到欄位 → **當場改成病人語言**(「兩週後回診」)
- [ ] 預覽 → 確認那張紙上沒有你的內部推理
- [ ] 定稿 → 列印/存 PDF 看一次

> 這一步過去會**預設把你的內部盤算印給病人**,只靠你記得刪掉。
> 2026-08-24 已改成預設不帶(#12 修復),但這是唯一會傷到人的路徑,親眼看一次。

### Step 7 — 匯出備份 ⚠️ 這步是你唯一的救命索

- [ ] 按「匯出病例」→ 確認真的下載到檔案
- [ ] 打開檔案看一眼:裡面有 `schema_version: 2`、`patients`、`cases`
- [ ] **關掉瀏覽器、重新開啟 app** → 病例還在
- [ ] 把檔案存到雲端硬碟(不是只留在下載資料夾)

### Step 8 — 把演練資料清乾淨

- [ ] 演練用的假病例全部刪除,或整個換到正式入口重來
- [ ] 確認正式入口是乾淨的 0 筆(或只有真實資料)

### Step 9 — 走一次反思(這是這套系統對你的真正用途)

- [ ] 打開任一病例 → 導航點「反思」→ 六問全部選填,填一兩問就好
- [ ] 存檔 → 病例詳情出現「臨床反思 N/6 已填」,只列你寫過的那幾問
- [ ] 一句都沒寫的病例,整塊不會出現(不會有一排空標題)

> 「病例記錄只是資料,反思才會把資料轉成臨床能力。」——你自己寫的。
> 六問一個都不強迫填,系統也絕不代你寫任何一句。

## 2. 開診當天的固定動作

| 時機 | 動作 | 為什麼 |
|---|---|---|
| 出門前 | 開 app,確認入口行是對的網址 | 開錯書籤是最容易犯、最難察覺的錯 |
| 開診前 | 按一次「匯出病例」 | 2026-08-11 演練中,匯出就是救回全庫的路徑 |
| 每個病人結束 | 存檔,確認病例列表數字有變 | 存檔失敗會跳紅框,但要看一眼 |
| 收工前 | 再匯出一次,丟上雲端 | 沒有自動備份;localStorage 不是保險箱 |

## 3. 還沒修、你要自己繞過的洞

| 洞 | 症狀 | 繞法 |
|---|---|---|
| 沒有自動備份 | 只有手動匯出 | 照 §2 的固定動作走 |
| 無容量監測 | localStorage 約 5–10MB;35 案 ≈ 149KB,短期不會爆 | 定期匯出即可 |
| `file://` 多 checkout 污染(M2) | 舊 worktree 的 `legacy/index.html` 會直寫 v1 鍵 | 不要用 `file://`;真要用就只留一份 checkout |
| 診前資料貼上用 `window.prompt()` | 無法多行預覽 | 貼上後在 SOAP 欄位裡自己核對 |
